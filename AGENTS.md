# Instrucciones del proyecto

## Prioridad y alcance

- Terminar BewerbungsTracker como un MVP funcional, con diseño profesional y responsive, para presentarlo a empresas como parte de la candidatura a prácticas FIAE.
- Después de terminar el MVP, abordar el rediseño del portfolio.
- Mantener Angular y TypeScript en el frontend, Python y Django REST Framework en el backend y SQLite como base de datos. Evitar dependencias innecesarias.
- Utilizar datos ficticios durante el desarrollo.

## Idiomas

- Escribir el código, los identificadores, los comentarios y los docstrings en inglés.
- Escribir la interfaz y los mensajes visibles para el usuario en alemán.
- Dar las explicaciones y escribir la documentación de aprendizaje en español sencillo, explicando qué se hace y por qué.
- Escribir el README público en alemán.
- Integrar la traducción de los comentarios y docstrings existentes que no estén en inglés en el siguiente bloque funcional, conservando la lógica.

## Forma de trabajo

- Revisar los archivos existentes antes de modificar el proyecto y conservar el trabajo previo.
- Trabajar por bloques funcionales completos, respetando el alcance solicitado para cada bloque.
- Añadir y ejecutar pruebas relevantes y las comprobaciones necesarias para verificar el bloque.
- Al finalizar cada bloque, resumir los cambios, los resultados de las comprobaciones y cualquier limitación pendiente.
- Usar el entorno virtual `.venv` para los comandos y las dependencias del backend.
- No guardar secretos reales en archivos versionados.
- El usuario realizará los commits desde su terminal PowerShell; no crear commits automáticamente.
- La Product Inventory API está en otro ordenador y no se ha revisado. No asumir su estructura ni depender de ella: el backend de BewerbungsTracker es independiente.
